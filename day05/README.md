## リサーチメモ（任意）

調べたURLや、理解した要点をメモしてください。

- RAGの基本（分割、埋め込み、検索、プロンプトへの注入）  
◎RAGの3要素  
・Retrieve:質問に関係する資料の断片を取得する  
・Augument:取得した断片を質問と一緒に入力へ加える  
・Generate:追加された情報を根拠に回答を生成する  

RAGの目的：LLMが最初から持っていない社内情報や更新された情報を問い合わせ時に参照できるようにすること。  

RAGの精度を上げる確認点  
1.資料品質：正本、更新日、対象部署、公開範囲が明確か  
2.分割品質：回答に必要な前後関係を保てているか  
3.検索品質：正しい断片が上位に入るか  
4.回答制約：資料にない内容を推測しない指示があるか  
5.評価データ：実際の質問と期待する根拠を用意したか  


〇分割：長い文章や資料を検索しやすいサイズに分割する  
⇒LLMやベクトル検索は長文より短いテキスト単位のほうが精度が高い  

〇埋め込み：テキストを数値ベクトルに変換し、意味的な類似度検索を可能にする  
⇒単語一致ではなく、意味ベースで検索できるようにする  

〇検索：ユーザーの質問に関連するチャンクを検索する  
⇒LLMに渡す情報量を絞り、不要なノイズを減らす  

〇プロンプトへの注入：検索結果をLLMのコンテキストとして渡す  
⇒モデルが外部知識を参照できるようにする

- 出典/ライセンスの確認方法  
RAGの出典：検索で取得したチャンクのメタデータから組み立てる  
モデルが自由生成した場合、存在しないURLや別ページを返す可能性があるため、検索メタデータの出典IDだけを返させ、URLはアプリケーション側で解決するほうがよい

- 検索ヒットなし時の設計  
検索結果が0の場合、LLMは根拠のない生成をしやすくなる。  
⇒無理に答えない or　代替情報を提示する
